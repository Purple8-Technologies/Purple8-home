02 · The Problem

Three operational gaps that automation has not yet reached

The plant floor runs massive rotary piercing mills, multi-pass drawing benches, induction furnaces, and hydraulic test stands. The data they generate is siloed, the compliance process is manual, and routing is still human-judgement-driven.

📡

Telemetry with no unified home

Each station emits sub-millisecond vibration, thermal, and pressure readings into isolated PLCs and SCADA historians. No layer correlates a furnace temperature drift with the wall-thickness variance it will cause three process steps later.

Root cause: data exists, but it has no graph.
📄

Compliance is a paper mountain

Every cylinder produces MTRs, UT/MPI inspection logs, heat-treatment certs, hydrostatic records, and serialised certificates for DOT, ASME, NASA, and Navy, in PDF, XLSX, XML, and proprietary mill formats. Matching to serial numbers is manual and error-prone.

A Navy QA inspector rejects at port. Not before loading.
🔄

Routing is unpredictable

Billets route between stations based on machine availability signals that are never aggregated into a single routing decision layer. A cylinder that should flow Piercing → Drawing → Annealing → NDT instead bounces, causing excess handling, extended cycle times, and utilisation imbalance.

No data-driven routing. No bottleneck visibility.

04 · Module 1 · Telemetry & Predictive Maintenance

Real-time plant intelligence, not post-mortem failure analysis

Purple8's BrickCoreStorage (Cortex) engine ingests high-frequency time-series data from mill sensors directly into the graph. The seal-and-evict memory model keeps peak RSS bounded regardless of how many readings accumulate.

// Cylinder production lifecycle — Journey Engine [Billet Cast] → [Rotary Piercing] → [Mandrel Drawing] → [Annealing] → [Straightening] → [UT Inspection] → [Hydro Test] → [Certified Ship-Ready] // SLA breach → HITL gate fires before part advances
Key property: If furnace temperature deviates during Annealing, the Journey Engine flags the cylinder, triggers HITL review, and emits a SLA_BREACHED graph edge, immutably, before the part advances. Plant engineers see a real-time alert, not a post-mortem failure report.
AEC module applied to mill equipment topology
Structural topology (aec/structural.py)

Originally built for BIM. Maps directly to plant topology: which piercing mill feeds which draw bench, critical machine dependencies, single points of failure (bridge detection) that would cascade a line stoppage.

MEP flow analysis (aec/mep.py)

Max-flow/min-cut (Edmonds-Karp) across production line capacity constraints. Identifies where throughput is genuinely bottlenecked vs where it is scheduling friction. Thermal zone simulation for induction furnace energy balance.

The AEC vertical was originally built for architects analysing building systems. The graph algorithms are domain-agnostic. A furnace feeding a draw bench is structurally identical to a boiler feeding a ventilation zone.

06 · Module 3 · Production Routing

Graph algorithms as the routing decision layer

All routing algorithms operate directly on the station graph stored in Purple8. No separate optimisation engine. No batch compute job. Results are real-time, always reflecting current machine availability.

Shortest path (Dijkstra)

Minimum-handling route for a cylinder of a given OD and wall thickness, across current machine availability. Updated on each station status change.

Betweenness centrality

Identifies which stations every production route passes through, representing the true bottlenecks. Directs capacity investment accurately rather than by gut feel.

Community detection (Louvain)

Clusters product families with similar routing profiles. Enables schedule batching to reduce furnace setups and tooling changeovers.

Link prediction

Surfaces latent correlations between upstream process parameters (pierce ratio, mandrel speed) and downstream inspection failures, giving process engineers earlier leverage than end-of-line defect analysis.

09 · Network-Level Intelligence

IOMA as a federated intelligence network

Each member runs their own Purple8 instance, air-gapped and privately owned. The SuperGraph layer federates read queries across member instances where data-sharing agreements exist, enabling industry-wide intelligence without centralising sensitive operational data.

What federated queries unlock

  • Industry defect pattern detection: a wall-thickness failure mode appearing at three manufacturers simultaneously surfaces as a material supply issue, not three isolated incidents
  • Cross-member cylinder lifecycle: a cylinder manufactured by CP Industries, filled by a distributor, and used at a medical facility has a complete chain-of-custody graph across all three organisations
  • Regulatory benchmark sharing: anonymised compliance pass-rates, inspection cycle times, and cert-matching accuracy across the IOMA membership
Data sovereignty preserved: each member's Purple8 instance is their own. The SuperGraph layer only reads what the sharing agreement permits. No centralised data warehouse. No cloud intermediary.
